# CloudSaver 使用与迁移指南

本文随 CloudSaver `1.0.1` 封装提供，固定上游版本为 `0.9.3`，目标为 fnOS `1.2.1010+`、x86_64（amd64；FPK 平台标识为 `x86`）。

本文说明安装、迁移和恢复流程；具体实测系统、通过项目与未验证项请查看对应版本的发行说明。

## 首次安装

1. 核对 FPK 的 SHA-256 与对应版本的 `SHA256SUMS.txt`。
2. 确认 `8008` 和 `18009` 端口未被其他服务占用，并确保安装期间可访问官方 Docker Hub。缺少 `python3-aiohttp` 时还需要访问设备已配置的软件源。
3. 在飞牛应用中心手动上传 FPK，等待固定版本程序完成下载、摘要校验与初始化。
4. 从飞牛桌面的 CloudSaver 图标进入网页；首次使用按上游界面完成注册和设置。

首次安装会在设备上获取官方程序，公共 FPK 本身不包含上游较新版本程序，也不包含个人账号、频道或网盘配置。全新设备的 JWT 密钥随机生成；导入已有配置时保留原配置中的必要密钥。

默认网页入口为 HTTP `8008`，内部后端只监听 `127.0.0.1:18009`。日常从飞牛桌面进入网页，在应用中心执行启动、停止和升级；需要远程 HTTPS 时使用自己管理的安全入口。

## 数据保存在哪里

飞牛登记入口为 `/var/apps/CloudSaver/`。实际存储卷由安装位置决定，不应假定某个固定磁盘目录。

| 位置 | 用途与处理方式 |
| --- | --- |
| `target/` | 本封装的程序与随包指南 |
| `var/runtime/` | 设备从官方来源获取的 CloudSaver 程序、Node、依赖与静态网页；程序文件由 root 所有，应用账户只读 |
| `var/data/` | 数据库与应用持久化数据，迁移和恢复的重点 |
| `var/config/` | 运行配置、JWT 等；迁移时与数据库一起保留 |
| `var/runtime-options.json` | root 管理的运行模式；迁移沿用原部署模式，恢复时与数据一起恢复 |
| `var/private/` | root 管理的下载与备份状态；其中的备份可能包含个人资料 |
| `var/logs/`、`var/cache/` 等 | 独立运行目录，日志按私密资料管理 |

CloudSaver 主程序使用独立低权限应用账户。数据和配置目录由该账户读写；安装器负责初始化权限。不要把生产 `data`、`config`、日志或备份复制进源码、FPK 暂存树或公开附件。

## 从 Docker 迁移

### 1. 盘点与备份

先确认实际运行版本、镜像摘要、端口、容器环境配置、全部挂载与其他持久化位置。不同版本的数据库结构可能不同，不使用旧版环境变量说明替代现场核对。

在旧服务停止写入后，保存数据库、完整 `data`、`config`、实际使用的插件及其他持久化内容，并记录版本和恢复所需的容器定义。核对备份可读、内容完整且权限受限。SQLite 的 WAL 或回滚日志属于一致性处理范围，不能只复制一个看起来像主数据库的文件。

备份是受保护的运行资料，不上传 GitHub。副本验证期间保留旧容器、镜像和原数据作为回退入口。

### 2. 安装通用封装并导入副本

先安装通用空配置 FPK，再通过应用中心停止新应用，确认服务已经结束后，**只在安装设备上**将备份导入原生应用的 `var/data/` 和 `var/config/`。

默认安装需要 `8008` 空闲。旧容器占用该端口时，先完成备份和独立临时端口验证，再安排切换窗口停止旧容器；此时仍保留旧部署。并行验证必须使用独立数据副本，避免两套服务同时写入同一数据库。

导入后的数据目录应归本机 CloudSaver 应用账户所有，保持配置和数据库的必要读写权限；目录使用 `0700`、私密配置文件使用 `0600`。保留 `var/runtime/` 程序文件的 root 所有权和只读访问方式，不从带有个人数据的运行目录反向生成安装包。

### 3. 核对所有配置

在启动新服务前，对备份和导入副本进行完整核对；启动后再通过页面与实际操作确认：

- 搜索频道的标识、名称、内容、顺序、启用或禁用状态，以及当前版本支持的其他频道属性。
- 账号与权限、网盘配置、插件及其配置、系统和网络设置。
- 数据库全部表和列的结构及内容，配置目录的文件清单与字节一致性。
- 真实搜索、页面访问、应用启停、升级与配置保留。

容器中的代理地址在宿主原生环境中可能有不同含义。先保留原配置，再在副本中实测；需要调整时记录具体原因和恢复方式。

仓库提供只读核验工具。以下示例路径必须替换为已准备好的离线副本路径；可在维护环境中分别比较 `data` 与 `config`：

```bash
python3 tools/config_integrity.py compare '/path/to/offline-backup/data' '/path/to/offline-import/data' --kind directory --offline-snapshot
python3 tools/config_integrity.py compare '/path/to/offline-backup/config' '/path/to/offline-import/config' --kind directory --offline-snapshot
```

工具只报告文件摘要、表结构、行数和一致性结果，不输出账号、频道或网盘凭据值。它仅用于已停写的完整副本，或经过正确备份流程生成的一致 SQLite 副本。

`--offline-snapshot` 表示调用者声明输入为离线副本，**不是原子备份已经成立的证明**。工具不制作备份，也不证明跨文件一致性。遇到 SQLite WAL 或回滚日志时，应重新确认备份方法；不要为通过核验而手动删除日志文件。

### 4. 切换与清理旧部署

若副本验证期间旧服务继续运行，正式切换前再次停止旧服务，生成最终一致性备份并同步新增改动，避免两边配置分叉。

原生版完成配置核对、真实搜索、启停和升级验收后，再按明确清单清理 CloudSaver 专属的旧容器、没有其他引用的镜像、独占编排记录及旧数据目录；网络和卷也需先核对是否共享。保留受限的恢复备份，确认其他应用与 NAS 管理入口正常。

在验收未通过时保留旧部署，并恢复原服务；本指南不提供全局清理命令。

## 搜索频道与 PanSou

原有搜索方式、个人频道和其他设置继续在 CloudSaver 页面管理。本期按需引用 PanSou 整理的公开频道资料，不启动 PanSou 引擎或新增搜索 API 服务。

补充频道时先备份现有配置，选择增量导入，对重复频道进行去重，再检查新旧频道的顺序和启用状态。已有的禁用项、排序和个性化名称应保留，不因补充公开资料而重置。

操作方法参考 [CloudSaver 作者使用文档](https://www.yuque.com/xiaoruihenbangde/ggogn3/ga6gaaiy5fsyw62l)，资料来源见 [PanSou 官方项目](https://github.com/fish2018/pansou)。文档中的公开频道示例不等同于任何人的个人配置。

## 更新与恢复

封装版本与上游版本分别管理。通过新版 FPK 更新封装；上游固定版本与摘要见随包 `upstream.json`，不会因为官方 `latest` 标签变化而自动更换。未来版本需要重新验证运行兼容性、数据格式、搜索功能和回退路径。

升级前由生命周期停止服务并保存配置快照。也可以在应用中心停止成功后，由管理员使用随包工具生成受限状态快照：

```bash
sudo python3 /var/apps/CloudSaver/target/tools/snapshot_state.py --var /var/apps/CloudSaver/var
```

快照包含 `data`、`config` 和 `runtime-options.json`，需按私密数据保管，并另行核实恢复材料。恢复到新安装时应一并恢复运行模式，避免改变旧配置的启动行为。应用内快照不能替代独立存储备份。

停止未完成或收尾状态不明确时，生命周期检查会阻止继续重启或升级。保留进程状态与日志，查明原因后再恢复；不要通过删除记录、绕过检查或强制杀进程来声称停止成功。

恢复前先停止原生应用，保存需要保留的后续改动，再恢复匹配的程序版本与配置快照。如使用上一版 FPK，应同时恢复与其兼容的数据。回到旧 Docker 服务时，也应先停止原生写入，使用已保留的旧镜像、定义和配套数据恢复，随后再次核对搜索与配置。

## 报告问题与隐私

向 [CloudSaver 项目](https://github.com/CyberShadowX/CloudSaver) 提交问题时，提供封装版本、上游版本、系统与架构、复现步骤和经过检查的错误摘要。截图与日志分享前检查个人频道、账号、Cookie、密钥及其他运行资料。

本项目的 MIT 许可覆盖封装代码；上游应用和第三方资料各自遵循其授权。CloudSaver 较新上游程序只在安装设备从官方来源获取，不随公开 FPK 或源码附件分发。
